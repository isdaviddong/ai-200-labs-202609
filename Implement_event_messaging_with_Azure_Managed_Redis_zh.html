在 Azure Managed Redis 中發佈與訂閱事件

在本練習中，您將部署 Azure Managed Redis 資源，並完成一個可從單一頁面發佈及訂閱 Redis 通道的 Python Flask Web 應用程式。您會加入程式碼，以使用 Microsoft Entra ID 連線至 Redis、發佈事件訊息、廣播至每個通道、格式化收到的訊息、在背景執行緒上接聽訊息，以及訂閱通道與模式。接著執行應用程式，並在發佈訊息時即時查看訊息送達。

本練習將執行的工作：

  • 下載專案起始檔案
  • 建立 Azure Managed Redis 資源
  • 將程式碼加入起始檔案以完成應用程式
  • 執行應用程式以發佈及訂閱訊息

本練習約需 30 分鐘完成。

開始之前

若要完成本練習，您需要：

  • Azure 訂用帳戶。如果您尚未擁有，您可以 註冊一個。
  • Visual Studio Code 安裝於其中一個 支援的平台。
  • Python 3.12 或更新版本。
  • 最新版的 Azure CLI。
  • Azure CLI 的 redisenterprise 延伸模組 2.75.0 或更新版本。稍後的步驟會為您安裝或升級此延伸模組。

下載專案起始檔案並部署 Azure Managed Redis

在本節中，您將下載應用程式的起始檔案，並使用指令碼初始化將 Azure Managed Redis 部署至您的訂用帳戶。Azure Managed Redis 部署需要 5 到 10 分鐘才能完成，因此您會先啟動部署，並在佈建期間將程式碼加入應用程式。

  1. 開啟瀏覽器並輸入下列 URL 以下載起始檔案。該檔案會儲存在您的預設下載位置。

    https://github.com/MicrosoftLearning/mslearn-azure-ai/raw/main/downloads/python/amr-pub-sub-python.zip

  2. 將該檔案複製或移動到系統中您想要進行專案作業的位置，然後將它解壓縮到資料夾中。

  3. 啟動 Visual Studio Code (VS Code)，並在選單中選取 File > Open Folder... ，然後選擇包含專案檔案的資料夾。

  4. 開啟 azdeploy.py 部署指令碼，並變更指令碼頂端的兩個值以符合您的需求，然後儲存變更。 Note: 請勿變更指令碼中的其他任何內容。

    "<your-resource-group-name>" # Resource Group name
"<your-azure-region>" # Azure region for the resources

  5. 在功能表列中選取 終端機 > 新增終端機 ，以在 VS Code 中開啟終端機視窗。

  6. 執行下列命令登入您的 Azure 帳戶。依照提示選取要用於本練習的 Azure 帳戶與訂用帳戶。

    az login

  7. 執行下列命令，確認您的訂用帳戶具有 Azure Managed Redis 所需的資源提供者。

    az provider register --namespace Microsoft.Cache

  8. 執行下列命令以安裝或升級 redisenterprise Azure CLI 延伸模組。若要設定資料庫的 Microsoft Entra ID 存取權，需要 2.75.0 或更新版本。

  9. 在終端機中執行下列命令以啟動部署指令碼。

    python azdeploy.py

  10. 當指令碼執行時，輸入 1 以啟動 1. Create Azure Managed Redis resource 選項。

    此選項會在資源群組尚不存在時建立它，然後部署 Azure Managed Redis。指令碼會等待部署完成（需要 5 到 10 分鐘），並在終端機中報告結果。讓指令碼繼續執行，並在部署佈建期間繼續下一節以加入程式碼。請定期返回終端機查看是否有錯誤。

    部署成功時，會出現如下的確認訊息，並返回選單：

    Azure Managed Redis 資源已成功建立：amr-exercise-<hash>

加入程式碼以連線至 Azure Managed Redis

在本節中，您將加入程式碼，以建立使用 Microsoft Entra ID 驗證的 Redis 用戶端。使用 Entra ID 表示應用程式永遠不會處理存取金鑰。

此 get_client() 函式會從 REDIS_HOST 環境變數讀取 Redis 端點，並呼叫 create_from_default_azure_credential() 以建置認證提供者。此提供者使用 DefaultAzureCredential 取得 Microsoft Entra 權杖，並在背景自動重新整理權杖，讓長時間執行的接聽程式連線保持已驗證狀態。用戶端會透過連接埠 10000 上的 TLS 連線，並將回應解碼為字串。

提示： 為保持正確的程式碼縮排，請將程式碼貼齊左邊界（第 1 欄），選取所有貼上的行，然後按 Tab ，使程式碼區塊與 BEGIN / END 標記對齊。如有需要，請按 Shift+Tab 以減少縮排。

  1. 尋找 # BEGIN CONNECTION CODE SECTION 註解，並在該註解下方加入下列程式碼。請務必確認程式碼縮排正確。

    def get_client() -> redis.Redis:
    """Create a Redis client for Azure Managed Redis using Microsoft Entra ID."""
    redis_host = os.environ.get("REDIS_HOST")

    if not redis_host:
        raise ValueError("REDIS_HOST environment variable must be set")

    # create_from_default_azure_credential uses DefaultAzureCredential to
    # acquire a Microsoft Entra token for Redis. The credential provider
    # refreshes the token automatically in the background so long-lived
    # connections (like the pub/sub listener) stay authenticated.
    credential_provider = create_from_default_azure_credential(
        ("https://redis.azure.com/.default",),
    )

    return redis.Redis(
        host=redis_host,
        port=10000,
        ssl=True,
        decode_responses=True,
        credential_provider=credential_provider,
        socket_timeout=30,
        socket_connect_timeout=30,
    )

  2. 儲存變更，並花幾分鐘檢閱程式碼。

加入程式碼以發佈事件

在本節中，您將加入程式碼以發佈訂單建立事件。這會示範將訊息傳送至單一通道的核心發佈作業。

此 publish_order_created() 函式會建置描述事件的字典、將其序列化為 JSON，並呼叫 publish()，並在 orders:created 通道上發佈。 publish() 方法會傳回收到訊息的訂閱者數目，應用程式會顯示此數目，讓您確認訊息已送達。

  1. 尋找 # BEGIN PUBLISH MESSAGE CODE SECTION 註解，並在該註解下方加入下列程式碼。請務必確認程式碼縮排正確。

    def publish_order_created(r: redis.Redis) -> dict:
    """Publish an order created event to the 'orders:created' channel."""
    order_data = {
        "event": "order_created",
        "order_id": f"ORD-{datetime.now().strftime('%Y%m%d%H%M%S')}",
        "customer": "Jane Doe",
        "total": 129.99,
        "timestamp": datetime.now().isoformat(),
    }
    channel = "orders:created"

    # publish() sends the message to every subscriber of the channel and
    # returns the number of subscribers that received it.
    subscribers = r.publish(channel, json.dumps(order_data))

    return {"channel": channel, "subscribers": subscribers, "message": order_data}

    Note: 起始檔案已包含 publish_order_shipped()、publish_inventory_alert() 與 publish_notification() 函式，因此您有多種事件類型可供使用。請花一點時間檢閱這些函式。

  2. 儲存變更，並花幾分鐘檢閱程式碼。

加入程式碼以廣播至所有通道

在本節中，您將加入程式碼，把單一訊息廣播至每個通道。廣播適用於所有訂閱者都應收到的全系統公告，無論他們訂閱哪個通道。

此 broadcast_to_all() 函式會逐一查看 AVAILABLE_CHANNELS ，並針對每個通道呼叫 publish() 來傳送相同訊息。它會加總所有通道的訂閱者數目，讓應用程式可以報告觸及多少訂閱者。

  1. 尋找 # BEGIN BROADCAST CODE SECTION 註解，並在該註解下方加入下列程式碼。請務必確認程式碼縮排正確。

    def broadcast_to_all(r: redis.Redis) -> dict:
    """Broadcast the same message to every channel using publish() in a loop."""
    announcement = {
        "event": "system_announcement",
        "message": "System maintenance scheduled for 2 AM",
        "priority": "high",
        "timestamp": datetime.now().isoformat(),
    }
    message = json.dumps(announcement)

    results = []
    total_subscribers = 0
    for channel in AVAILABLE_CHANNELS:
        # Send the same message to multiple channels for multi-channel delivery.
        count = r.publish(channel, message)
        total_subscribers += count
        results.append({"channel": channel, "subscribers": count})

    return {
        "channels": results,
        "total_subscribers": total_subscribers,
        "message": announcement,
    }

  2. 儲存變更，並花幾分鐘檢閱程式碼。

加入程式碼以格式化收到的訊息

在本節中，您將加入程式碼以格式化傳入訊息供顯示。背景接聽程式會針對收到的每則訊息呼叫此函式，讓網頁能顯示簡潔的摘要。

此 format_message() 函式會從原始 pub/sub 訊息讀取通道、模式與資料。它會剖析 JSON 承載，並擷取事件類型及一組已知欄位，例如 order_id 與 customer。如果承載不是有效的 JSON，則會改為傳回原始值，以免遺失任何內容。

  1. 尋找 # BEGIN MESSAGE FORMATTING CODE SECTION 註解，並在該註解下方加入下列程式碼。請務必確認程式碼縮排正確。

    def format_message(message: dict) -> dict:
    """Parse a pub/sub message and extract relevant fields for display."""
    timestamp = datetime.now().strftime("%H:%M:%S")
    channel = message.get("channel", "unknown")
    pattern = message.get("pattern")

    try:
        data = json.loads(message["data"])
    except (json.JSONDecodeError, TypeError):
        # Non-JSON payloads are returned as-is under a "raw" key.
        return {
            "timestamp": timestamp,
            "channel": channel,
            "pattern": pattern,
            "event": None,
            "details": {"raw": message.get("data")},
        }

    # Pull out the fields that the demo events include so the UI can
    # display a clean summary of each message.
    field_names = [
        "order_id", "customer", "total", "tracking_number",
        "product_name", "current_stock", "message",
    ]
    details = {name: data[name] for name in field_names if name in data}

    return {
        "timestamp": timestamp,
        "channel": channel,
        "pattern": pattern,
        "event": data.get("event", "unknown"),
        "details": details,
    }

加入程式碼以接聽訊息

在本節中，您將程式碼加入 listen_messages() 方法。此方法屬於 PubSubManager 類別。此方法會在背景執行緒上執行，讓應用程式能持續接收訊息，同時仍可回應 Web 要求。

此方法會逐一查看 pubsub.listen()；此呼叫會封鎖，並在訊息發佈時產生訊息。它會處理 message （直接通道）與 pmessage （模式）兩種類型，使用 format_message() 格式化每則訊息，並將其加入網頁輪詢的執行緒安全緩衝區。錯誤會被擷取並顯示為系統訊息，讓 UI 中可看見失敗。

  1. 尋找 # BEGIN MESSAGE LISTENER CODE SECTION 註解，並在該註解下方加入下列程式碼。請務必確認程式碼縮排正確。

    def listen_messages(self) -> None:
    """Background thread that reads messages from subscribed channels."""
    self.listener_active = True
    try:
        # listen() blocks and yields messages as they are published.
        for message in self.pubsub.listen():
            if not self.listening:
                break

            # Handle both direct channel messages and pattern messages.
            if message["type"] in ("message", "pmessage"):
                self._add_message(format_message(message))

    except Exception as e:
        if self.listening:
            self._add_message({
                "timestamp": datetime.now().strftime("%H:%M:%S"),
                "channel": "system",
                "pattern": None,
                "event": "listener_error",
                "details": {"error": str(e)},
            })
    finally:
        self.listener_active = False

  2. 儲存變更，並花幾分鐘檢閱程式碼。

加入程式碼以訂閱通道與模式

在本節中，您將程式碼加入 subscribe_to_channel() 與 subscribe_to_pattern() 方法。這是 Redis pub/sub 的兩種主要訂閱策略：針對特定事件的直接通道訂閱，以及用於萬用字元比對的模式訂閱。

此 subscribe_to_channel() 方法會呼叫 subscribe() 以登錄對單一通道的關注，而 subscribe_to_pattern() 會呼叫 psubscribe()，以使用如下模式比對多個通道： orders:*。每次變更訂閱後，程式碼會重新啟動接聽程式，讓它開始接收新通道上的訊息。

  1. 尋找 # BEGIN SUBSCRIBE CHANNEL/PATTERN CODE SECTION 註解，並在該註解下方加入下列程式碼。請務必確認程式碼縮排正確。

    def subscribe_to_channel(self, channel: str) -> str:
    """Subscribe to a specific channel using subscribe()."""
    self.pubsub.subscribe(channel)  # Register interest in the channel.
    self.restart_listener()
    return f"Subscribed to channel: {channel}"

def subscribe_to_pattern(self, pattern: str) -> str:
    """Subscribe using a pattern with psubscribe() (e.g. 'orders:*')."""
    self.pubsub.psubscribe(pattern)  # Register interest in matching channels.
    self.restart_listener()
    return f"Subscribed to pattern: {pattern}"

執行應用程式

在本節中，您將執行已完成的 Flask 應用程式，從單一網頁發佈及訂閱訊息。左側面板用於發佈事件及管理訂閱，右側面板則顯示上次發佈的結果，以及收到訊息的即時串流。

  1. 在終端機中執行下列命令以啟動應用程式。如有需要，請在執行命令前參考本練習稍早的命令來啟用環境並載入環境變數。如果您已離開 client 目錄，請先執行 cd client 。

    python app.py

  2. 開啟瀏覽器並瀏覽至 http://localhost:5000 以存取應用程式。

  3. 在左側面板的 Subscriptions 區域中，選取通道方塊以開啟下拉式清單，選擇 notifications，然後選取 Subscribe。成功訊息會確認訂閱，而 Active subscriptions 清單會更新以包含該通道。您必須先訂閱通道，才能收到其訊息。

  4. 在左側面板的 Publish Events 區域中，選取 Notification。右側面板會顯示發佈結果，包括通道及觸及的訂閱者數目。一兩秒內，訊息會出現在 Received Messages 清單中，因為背景接聽程式已將訊息傳遞至您的訂閱。

  5. 選取 Inventory Alert。發佈結果會顯示訊息已傳送至 inventory:alerts 通道，但不會出現在 Received Messages 中，因為您只訂閱了 notifications。

  6. 在左側面板的 Subscriptions 區域中，輸入 orders:* 至模式方塊，然後選取 Subscribe to Pattern。這會訂閱以 orders:*開頭的每個通道，而該模式會出現在 Active subscriptions 清單中，與 notifications 並列。

  7. 選取 Order Created，然後選取 Order Shipped。兩則訊息都會出現在 Received Messages 清單中，因為 orders:* 模式會同時比對 orders:created 與 orders:shipped 通道。

  8. 選取 Broadcast to All ，以將單一公告傳送至每個通道。請查看 Received Messages 清單針對符合目前訂閱的每則訊息即時更新。

  9. 選取 Unsubscribe from All 以清除訂閱，然後再次選取 Broadcast to All 。確認 Received Messages 不再收到任何新訊息，因為您已沒有作用中的訂閱。

疑難排解

如果您在完成本練習時遇到問題，請嘗試下列疑難排解步驟：

驗證 Azure Managed Redis 資源部署

  • 瀏覽至 Azure portal 並找出您的資源群組。
  • 確認 Azure Managed Redis 資源顯示的 Provisioning State 為 Succeeded。
  • 執行部署指令碼的 Check deployment status 選項，並在建立資料庫及設定存取權之前，確認叢集和資料庫已就緒。 解決部署失敗
  • 如果部署失敗，通常是因為所選區域中的 SKU 暫時容量不足。
  • 依照畫面上的指引結束指令碼，將指令碼頂端附近的 location 變數變更為其他區域，例如 eastus2、australiaeast 或 canadacentral，然後再次執行指令碼並選擇選項 1。
  • 失敗的資源會在下次嘗試前自動刪除。 檢查驗證與存取權
  • 執行下列命令，確認您已登入 Azure CLI： az account show。
  • 確認部署指令碼的 Create database and configure access 選項已成功完成，讓您的帳戶具有資料庫的資料存取原則。
  • 如果應用程式報告驗證錯誤，請稍候片刻再試一次，因為存取原則指派可能需要一點時間才會生效。

檢查程式碼完整性與縮排

  • 確認所有程式碼區塊都已加入 pubsub_functions.py 中正確的區段，位於適當的 BEGIN/END 註解標記之間。
  • 確認 Python 縮排一致（使用空格，而非定位字元）。 listen_messages()、subscribe_to_channel() 與 subscribe_to_pattern() 方法位於 PubSubManager 類別內，因此其程式碼必須縮排一層。
  • 確認在指定區段之外沒有任何程式碼被意外刪除或修改。

驗證環境變數

  • 確認專案根目錄中同時存在 .env 與 .env.ps1 檔案，且包含 REDIS_HOST 值。
  • 在 Bash 中執行 source .env ，或在 PowerShell 中執行 . ..env.ps1 ，以將環境變數載入終端機工作階段。

沒有出現訊息？

  • 確認您已訂閱要發佈至的通道。訊息只會送達您已訂閱的通道或模式。
  • 在瀏覽器中檢查 Active Subscriptions 清單，以確認目前的訂閱。
  • 確認應用程式仍在終端機中執行，且頁面顯示訊息串流正在更新。

檢查 Python 環境與相依性

  • 確認在執行應用程式前已啟用虛擬環境。
  • 確認 requirements.txt 中的所有套件都已成功安裝，可執行 pip list。
